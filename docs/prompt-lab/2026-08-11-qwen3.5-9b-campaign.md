# Prompt Lab campaign — `qwen/qwen3.5-9b`

Date: 2026-08-11
Benchmark: same as the gemma-4-12b campaign — `tools/prompt-lab/data/positions.json`
(seed 42; screen = first 150 positions, final = first 600), one request per
position, `temperature 0`, no correction retries, `reasoning_effort: "none"`
(qwen3.5-9b is also a reasoning model: without the flag, `content` comes back
empty exactly like gemma-4 — re-verified live before the run).

## Verdict

**Winner: `v6-pgn-completion`** — the raw-completion PGN continuation. The
prompt that failed hardest on gemma-4 is the strongest on qwen3.5 — and the
per-model `ModelAdapter` layer exists precisely because of results like this.

| variant (final, n=600) | match     | ±se  | match+legal | illegal | mean ms |
| ---------------------- | --------- | ---- | ----------- | ------- | ------- |
| **v6-pgn-completion**  | **10.7%** | 1.3% | 74.8%       | 151     | 1907    |
| v7-cot-legal           | 7.7%      | 1.1% | 89.7%       | 62      | 8586    |
| v8-karpov-legal        | 6.8%      | 1.0% | **98.7%**   | 8       | 1742    |
| v0-baseline (control)  | 3.3%      | 0.7% | 33.0%       | 402     | 1327    |

Against the production control at equal n: **match 10.7% vs 3.3%** (7.4 pp,
far beyond noise) and legality 74.8% vs a catastrophic 33.0%. The current
app prompt makes qwen3.5 play essentially random chess (2 of 3 replies are
illegal → correction → random fallback). An adapter is emphatically
justified.

## Screen (n=150), all nine variants

v7-cot-legal 10.0%/89.3%, v6-pgn-completion 9.3%/73.3%,
v8-karpov-legal 6.7%/**100.0%**, v1-legal-list 6.7%/99.3%,
v4-cot 4.0%/38.0% (15.0 s!), v0-baseline 4.0%/31.3%, v3-board 3.3%/30.0%,
v5-fewshot 2.0%/28.7%, v2-uci 0.7%/3.3% (132 unparseable).

What differs from gemma-4:

- **PGN continuation works on qwen** (chat-tuned gemma ignored it). Replies
  look like ` Bd7 14. e3 O-O` — the model continues the game; the parser
  takes the first move.
- **The legal-move list is still the legality king** (v8 hit 100% on the
  screen, 98.7% at n=600) but costs accuracy on this model relative to v6.
- **The baseline prompt is far worse on qwen than on gemma** (33% vs 60%
  legality) — per-model prompting matters even more here.
- v4-cot runs 15 s/position on qwen — unusable, and only 38% legal.

## Failure flavor (Claude replay)

qwen's misses are not gemma's checking reflex — they are "PGN-plausible"
quiet continuations: e.g. `2rb2k1/1qB2pp1/1P2b1np/1BN1p3/3pP3/8/2Q2PPP/1R5K b`
— game **Rxc7!** (removing the c7/b6 bind); model **Bf6**, a natural-looking
regrouping that concedes the bind. The model continues a typical game rather
than resolving the concrete position.

## No round 2

The race consumed the campaign's 1–2 h budget (9 screens + 3 finals +
the n=600 baseline ≈ 2,800 requests). Round-2 candidates from the gemma
campaign (v7, v8) were already in the roster and took two of the three
final slots — the marginal-return step was effectively pre-paid.

## Adapter recommendation (implemented as Task 16): a two-stage adapter

`v6-pgn-completion` cannot be transplanted alone: it ignores
`ctx.correction`, and at temperature 0 a production retry would resend the
same prompt and get the same illegal move — its 25% illegal rate would
land in the random fallback every time. Instead, `qwen35.ts` uses the
measured winner for the first attempt and the measured legality king for
retries:

- **Attempt 1** (`ctx.correction` absent): the v6 PGN-completion prompt
  (GM headers + movetext + move-number lead), `parseFirstSan`-style parse.
- **Retries** (`ctx.correction` present): the v8 legal-list chat prompt,
  `parseSanCandidates`.
- `matches: (id) => id.includes('qwen3.5')`;
  `sampling: { temperature: 0, maxTokens: 64, reasoningEffort: 'none' }`.

Expected production behavior: ~75% of moves from the strongest prompt,
nearly all of the remaining 25% recovered legally by the retry stage
(~99% of retries legal), fallback-random only in the residue —
versus ~67% random-fallback today.
